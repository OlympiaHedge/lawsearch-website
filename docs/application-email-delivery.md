# Application and CV email delivery

All CV registration links and per-job Apply links use `/apply` and POST `/api/applications`. Every successful response follows email-provider acceptance of an email to jacob.fisher@hamptonhillsgroup.com, with candidate details, role/reference, message, CV and all supporting documents attached. Reply-To is the applicant. Existing Resend runtime secrets and sender configuration are reused.

Applicants can include a required CV and up to three optional PDF/DOC/DOCX supporting documents: 5 MiB each, 10 MiB combined. Server validation checks type signatures, sizes, consent, practice area, origin and submission limits. Documents remain in restricted R2 storage with records in D1. Recruiter downloads, including supporting documents, require the existing recruiter authorization.

Storage completes before delivery. A provider failure keeps the application and files, returns an honest error and permits retry with the same submission ID. Stable provider idempotency keys and immutable stored content prevent duplicate email on retries within the provider's retention window. Recruiter access shows delivery status and offers a bounded pending retry. The existing job-alert dispatcher also retries pending application emails whenever it runs. No new scheduler is enabled by this change. Unconfirmed attempts older than 23 hours are held for manual provider review to avoid duplicate sends after key expiration. No email is sent for historical applications merely by deploying this change.

Verification: `node --test tests/applications.mjs`, `node node_modules/typescript/bin/tsc --noEmit`, then the Sites build helper. The tests use real SQLite migrations and mocked R2/email transport to cover file integrity, selected role, duplicate submissions, failed sends and retry, expired idempotency, upload limits and anonymous access denial. A provider acceptance response is not proof of inbox placement; inbox/spam confirmation requires access to the destination mailbox.
